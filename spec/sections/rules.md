# Rules Section

## Description
The Rules section defines behavioral constraints and guidelines for the module.

## Syntax
```markdown
## Rules

- Rule 1
- Rule 2
- Rule 3
```

## Rules
- Use bullet list format
- Each rule should be a single line
- Rules should be actionable and specific

## Example
```markdown
## Rules

- Never expose secrets in logs
- Validate all inputs before processing
- Use constant-time comparison for tokens
- Rotate secrets every 90 days
```
